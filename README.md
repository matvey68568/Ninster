# Ninster

Установка программ в один клик — аналог [Ninite](https://ninite.com/) с более широким
каталогом (139 программ), работающий поверх **winget** (менеджер пакетов Microsoft).

Открыл → отметил нужные программы галочками → нажал «Установить». Дальше Ninster сам
скачает и установит всё по очереди, без кликов по инсталляторам и рекламных «бандлов».

> **Важно про «работает на любом ПК».** Ninster не качает программы сам — он отдаёт
> команды системному инструменту `winget`. Это плюс (огромный актуальный каталог,
> автоматическое обновление версий, проверенные источники), но `winget` должен
> присутствовать в системе. На Windows 10/11 он предустановлен как часть «App Installer»
> из Microsoft Store; на старых сборках его нужно один раз установить. Подробнее — в
> разделе «Требования».

## Возможности

- 🖱 **Один клик** — выбираешь галочками любые программы из 11 категорий и ставишь их разом.
- 🔍 **Поиск и фильтр** — мгновенный поиск по названию и категориям.
- 📦 **139 программ** — браузеры, мессенджеры, офис, медиа, графика, разработка, утилиты,
  безопасность, архиваторы, облако, игры.
- 🎯 **Тихая установка** — без всплывающих окон (`--silent`), с автосогласием на лицензии.
- 📊 **Живой прогресс** — полоса прогресса, статус каждой программы (Ожидание / Установка /
  Готово / Ошибка) и журнал выполнения.
- 🔐 **Автозапуск от администратора** — приложение само запрашивает UAC один раз при
  запуске, поэтому установка всех программ идёт без единого лишнего клика.
- 🪶 **Один файл** — собранный `Ninster.exe` ничего не ставит и работает «из коробки».

## Требования

| Компонент | Версия | Как проверить |
|---|---|---|
| Windows | 10 (1809+) или 11 | — |
| winget | 1.x | `winget --version` в терминале |

### Если winget не найден

Ninster сам это определяет и подсветит предупреждение. Установить winget:

1. Открой **Microsoft Store** и установи приложение **«App Installer»**
   (оно включает winget).
2. Либо установи [последнюю версию App Installer с GitHub](https://github.com/microsoft/winget-cli/releases).
3. Перезапусти Ninster.

## Установка и запуск

### Готовый exe (для пользователей)

Скачай `dist/Ninster.exe` и запусти. Windows SmartScreen может спросить подтверждение —
нажми «Подробнее → Выполнить в любом случае» (это нормально для программ без цифровой
подписи). Файл переносимый: можно положить на флешку и запускать на любом ПК.

### Из исходников (для разработчиков)

```bash
# 1. Создать виртуальное окружение (Python 3.10+)
python -m venv .venv

# 2. Активировать и поставить зависимости
#    Windows:
.venv\Scripts\activate
pip install -r requirements.txt

# 3. Запустить
python main.py
```

## Сборка в exe

```bash
python build.py
```

Результат: `dist/Ninster.exe` (один файл, ~19 МБ, иконка встроена).

Сборка автоматически:
- генерирует иконку `assets/icon.ico` (если её нет) через `make_icon.py`;
- упаковывает приложение и `customtkinter` в один исполнимый файл через PyInstaller;
- вшивает в exe манифест `requireAdministrator` через `patch_manifest.py`, чтобы
  программа запрашивала UAC один раз при запуске (а не при установке каждой программы).

## Как добавить программу в каталог

Все программы лежат в одном месте — файле `catalog.py`, списком `CATALOG`:

```python
App("<winget-id>", "Название", "категория", "Краткое описание"),
```

1. Найди winget ID нужной программы:
   ```bash
   winget search имя_программы
   ```
2. Добавь строку в нужную категорию в `catalog.py`.
3. Проверь, что ID корректен, запустив валидатор:
   ```bash
   python validate_catalog.py
   ```
4. Пересобери: `python build.py`.

> 💡 Для программ из Microsoft Store ID выглядит как `9XXXXXXXXXXX` (магазинный
> идентификатор). Их `winget search` находит с флагом `--source msstore`.

## Как это устроено

Ninster для каждой выбранной программы выполняет:

```bash
winget install --id <id> --exact --silent \
  --accept-package-agreements --accept-source-agreements \
  --disable-interactivity
```

Установка идёт **последовательно** в фоновом потоке, чтобы интерфейс не зависал;
каждая команда — отдельный процесс с перехватом вывода, который строится в журнал.

## Ограничения

- Скорость зависит от сети и от самих пакетов: тяжёлые IDE (Visual Studio) и
  системы (Docker) ставятся заметно дольше.
- Некоторые пакеты winget всё же могут запросить окно подтверждения (например, вход
  в учётную запись) — это редкость, но не исключено.
- Не все программы мира есть в winget; список в `catalog.py` — осознанно
  отобранный популярный набор, его легко расширять.

## Структура проекта

```text
ninster/
├── main.py              # Точка входа: GUI (customtkinter), логика интерфейса,
│                        # фильтрация, прогресс, журнал, запуск установки
├── catalog.py           # Каталог программ: список App(id, имя, категория, описание)
│                        # и словарь CATEGORIES. Сюда добавляются новые программы
├── installer.py         # Движок установки: обёртка над winget, фоновый поток,
│                        # статусы (QUEUED/INSTALLING/DONE/ERROR/SKIPPED), колбэки
├── build.py             # Сборка в один .exe через PyInstaller (вызывает make_icon.py)
├── make_icon.py         # Генерация assets/icon.ico (синий квадрат + стрелка загрузки)
├── patch_manifest.py    # Вшивает манифест requireAdministrator в готовый exe (pefile)
├── validate_catalog.py  # Проверяет каждый winget ID из catalog.py командой `winget show`
├── smoke_test.py        # Дымовой тест GUI: строит окно, проверяет выбор/фильтр/прогресс
├── requirements.txt     # Зависимости: customtkinter, pyinstaller, pillow
├── README.md            # Этот файл
├── assets/
│   └── icon.ico         # Иконка приложения (генерируется make_icon.py)
├── build/               # (создаётся при сборке) служебные файлы PyInstaller
├── dist/
│   └── Ninster.exe      # (создаётся при сборке) готовый исполняемый файл
└── .venv/               # (создаётся локально) виртуальное окружение Python
```

### За что отвечает каждый модуль

| Файл | Роль | Зависит от |
|---|---|---|
| `main.py` | Пользовательский интерфейс и связка всего | `catalog`, `installer` |
| `catalog.py` | Данные — что доступно для установки | — |
| `installer.py` | Запуск `winget` и статусы установки | — |
| `build.py` | Сборка в exe | `make_icon.py`, `patch_manifest.py` |
| `make_icon.py` | Генерация иконки | — |
| `patch_manifest.py` | Вшивка манифеста администратора в exe | — |
| `validate_catalog.py` | Проверка корректности ID | `catalog` |
| `smoke_test.py` | Автотест интерфейса | `main`, `catalog` |

**Поток управления:** `main.py` (GUI) читает список из `catalog.py`, отображает его,
и по нажатию «Установить» создаёт `installer.Installer` (фоновый поток), который по
очереди вызывает `winget install`. Статусы и строки журнала возвращаются обратно в UI
через колбэки и потокобезопасную очередь.
